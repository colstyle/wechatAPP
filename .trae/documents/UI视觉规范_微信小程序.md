# UI 视觉规范（基于《微信小程序 UI 设计高级参考标准》）

## 1. 适用范围
- 适用端：微信小程序（竖屏为主），覆盖用户端与店主端（admin）。
- 目标：统一字体/色彩/布局/组件与反馈规范，保证一致性、可读性与可操作性。

## 2. 全局布局规范（rpx）
- 页面安全区：内容避免遮挡状态栏/导航栏/TabBar；底部存在 TabBar 的页面需预留 96rpx。
- 导航栏：高度 88rpx；标题居中；次级页面左上角必须可返回。
- TabBar：高度 96rpx；最多 5 项（本项目 4 项）。
- 页面边距：左右内边距统一 20rpx；区块间距 16rpx；页面上下外边距 20rpx。
- 点击热区：≥44×44px（约 88×88rpx）；可点击元素间距 ≥8px（约 16rpx）。

## 3. 字体与排版
- 字体：系统字体（iOS PingFang SC / Android 思源黑体），不引入第三方字体。
- 字号与字重（建议落地为 token）：
  - H1：44rpx / 600 / #000
  - H2：34rpx / 600 / #000
  - Body：30rpx / 400 / #333
  - Assist：28rpx / 400 / #666
  - Hint：24rpx / 400 / #999
  - Emphasis：30rpx / 500 / 品牌主色
- 行高：正文 1.4–1.6 倍；标题约 1.2 倍。
- 文案规则：每页 1 个核心目标；按钮/标题尽量短；错误文案必须给出“原因 + 解决方案”。

## 4. 色彩系统（与现有 TabBar 配置对齐）
- 品牌主色（Primary）：#FF6B6B（与 tabBar.selectedColor 一致）。
- 文字色：#000（标题），#333（正文），#666（辅助），#999（提示）。
- 分割线/描边：#EEEEEE。
- 背景：#FFFFFF（页面底），#F7F7F7（列表/卡片区底，若需）。
- 状态色（用于订单/结果态）：
  - Success：#2ECC71（已取衣/成功）
  - Info：#2F80ED（已支付/信息）
  - Warning：#F2C94C（提醒/库存紧张）
  - Danger：#EB5757（逾期/错误）
- 对比度：正文文字与背景 ≥4.5:1；按钮文本与按钮背景 ≥3:1。

## 5. 圆角、阴影、分层
- 圆角：
  - Button：10rpx
  - Card：16rpx
- 阴影（卡片）：0 2rpx 8rpx rgba(0,0,0,0.10)；避免重阴影与渐变。

## 6. 图标规范
- 尺寸：24×24px（48×48rpx）为主；必要时 32×32px（64×64rpx）。
- 线条：2px（约 4rpx），统一圆角；禁用渐变与拟物。
- 颜色：遵循文字层级（主色/正文色/提示色）。

## 7. 核心组件规范
### 7.1 按钮
- 主按钮：高度 96rpx；填充主色；圆角 10rpx；字重 600。
- 次按钮：高度 ≥80rpx；描边 + 主色文字；背景透明；圆角 10rpx。
- 文字按钮：无背景/无边框；用于弱操作（如“取消”“稍后”）。
- 禁用：透明度 30%，不可点击；表单未通过校验时必须禁用提交。

### 7.2 列表
- 行高：≥80rpx；整行可点击区域尽量覆盖主操作。
- 分割线：1px #EEEEEE；左右缩进 20rpx。
- 单行最多 2 个操作（主操作为整行，次操作右侧）。

### 7.3 卡片（商品/订单）
- 样式：圆角 16rpx；轻阴影；内边距 20rpx；卡片间距 16rpx。
- 商品卡：图片 1:1；名称 ≤2 行；价格突出（字重 600）。

### 7.4 表单
- 标签对齐：全局统一（建议左对齐）；同一表单不可混用。
- 校验：实时校验；错误紧贴字段；表单顶部可显示错误汇总与定位。
- 提交：提交中显示加载态并防止重复提交。

## 8. 反馈与状态设计
- 加载：操作 >1s 必须显示进度（局部 skeleton/加载动画优先）。
- 成功：wx.showToast，1.5s 自动消失，不打断流程。
- 错误：wx.showModal 或页面内错误区；必须给出可执行解决方案。
- 网络错误：全屏状态页 + “重试”按钮，避免死胡同。

## 9. 页面级元信息规范（小程序语境）
- 导航栏标题：与页面核心目标一致；避免冗长。
- 分享：为首页/商品详情/订单详情提供 share 标题与封面图（遵循图标与图片规范）。

## 10. 图片与性能
- 图片：优先 WebP；按 2x/3x 出图；避免“大图缩小”。
- 列表图片：启用懒加载；长列表建议虚拟列表。
- 结构：减少 WXML 层级，避免过度嵌套；避免 scroll 事件高频 setData。
