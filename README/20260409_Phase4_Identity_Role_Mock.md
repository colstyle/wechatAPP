# Phase 4：身份与权限调试（Mock 固定身份）

## 背景

真机调试阶段，如果每次登录都生成新用户，很难复现问题、也无法稳定验证「用户端/店主端」权限分流。

本阶段提供两套调试方式：

- 数据库改 `role`：最贴近真实线上
- Mock 固定身份 `mockOpenid`：效率最高，测试最常用

## 角色规则

系统以 `users.role` 控制权限与界面分流：

- 普通用户：`role = 1`（兼容 `user`）
- 店主/管理员：`role = 2`（兼容 `admin`）

店主接口会做强校验：非店主调用会返回 403。

## 真机调试前提

- 后端服务监听 `0.0.0.0:8000`，同一网络下手机可访问电脑
- 小程序「设置」页配置后端地址（真机不要填 `127.0.0.1`）

## 方式一：数据库改 role（最贴近真实）

1. 在数据库工具中打开 `Celestial_db.users`
2. 找到你当前登录对应用户（可用 `nickname` 或 `openid` 识别）
3. 修改 `role` 字段

示例 SQL：

```sql
-- 设为店主/管理员
UPDATE users SET role = '2' WHERE id = 21;

-- 设为普通用户
UPDATE users SET role = '1' WHERE id = 21;
```

改完后：

- 清除小程序缓存 / 重新进入
- 重新登录获取新 token 后生效

## 方式二：Mock 固定身份（推荐，效率最高）

适用于测试环境快速切换身份，避免不断新增用户记录。

操作：

1. 打开小程序「设置」页
2. 填写模拟身份 `mockOpenid`
   - 普通用户：`user_1`
   - 店主/管理员：`admin_1`
3. 点击「重新登录」
4. 清缓存 → 重新进入小程序（确保旧 token 不影响）

效果：

- 永远是同一个用户，便于反复调试
- `admin_1` 会自动以店主身份进入管理界面

## 如何确认当前身份

任选一种：

- 页面确认：在「我的」页看到「店铺管理」入口/自动进入管理端，即为店主
- 网络确认：真机调试里查看 `GET /api/user/profile` 返回的 `data.role`

## 常见问题排查

- 身份切换不生效：先点「重新登录」，再清缓存重进（旧 token 会缓存权限）
- 用户记录越来越多：不要用随机 `code` 生成身份；使用 `mockOpenid` 固定身份
- 真机无法访问后端：检查后端地址是否为电脑局域网 IP，且后端监听 `0.0.0.0`
