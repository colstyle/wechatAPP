## 📅 Phase 2 - 店主管理与支付框架的实现

### 💡 架构设计与开发思路 (Architecture & Thoughts)
- **基于角色的访问控制 (RBAC) 引入**：为了区分普通用户与店主，我们在数据库 `users` 表中引入了 `role` 字段。后端通过该字段对敏感接口（如全量订单查询、退款、扣费）进行权限校验。前端则根据 `role` 动态展示“店铺管理”入口，确保非管理员无法触达管理功能。
- **店主管理业务闭环**：Phase 2 重点打通了“租赁中 -> 归还核验 -> 财务结算”的店主操作链路。通过提供列表搜索与详情管理，店主可以对每一笔订单执行“一键退押”或“手动扣费”。
- **标准化支付工具类 (WeChatPayV3)**：考虑到未来业务合规后的真实支付需求，我们预先构建了符合微信支付 V3 规范的工具类框架。它集成了签名生成、API V3 请求构造及退款申请逻辑。目前业务逻辑已通过该框架进行路由，只需在未来替换真实证书即可上线。
- **异步操作的 UI 反馈**：管理端涉及大量的金钱操作。我们通过 Modal 弹窗结合 Loading 状态，确保每一笔退款或扣费操作都有明确的进度反馈，并强制要求输入操作原因以留存记录。

### 🚀 新特性 (New Features)
- **【管理员专用入口】**：在“我的”页面，针对管理员角色展示醒目的“店铺管理”功能项。
- **【全量订单列表管理】**：支持按单号、用户昵称模糊搜索，支持按订单状态（待取衣、租赁中、待审核等）快速切换视图。
- **【订单管理工作台】**：
    - **一键退押**：支持在待审核状态下快速全额或部分退还押金。
    - **手动扣费**：支持店主根据逾期时长或衣物损毁情况，灵活输入扣费金额与理由。
    - **换款接口预留**：提供了换款逻辑的后端接口，支持修改订单内的商品信息。
- **【微信支付 V3 协议框架】**：
    - 封装了 JSAPI 下单及退款接口请求。
    - 实现了符合 V3 标准的退款流水号（REF/DED 前缀）生成机制。
