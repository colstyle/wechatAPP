## 📅 Phase 3 - MVP 精简与闭环打通

### 🎯 目标

- 聚焦线下 24h 自助租衣的最小可用闭环：选日期 → 选衣 → 下单 → 支付（模拟）→ 取衣 → 还衣 → 店主退押/扣费。
- 降低页面与接口耦合度，减少不影响闭环的分支功能，优先稳定可用性与体验。

### ✅ 闭环范围 (当前版本)

- **用户端**：日期筛选、商品列表与详情、提交订单、支付页、订单列表与详情、取衣/还衣操作、AI 客服入口。
- **店主端**：订单列表/筛选/搜索、订单详情、退押金、扣押金。

### 🔧 关键改动明细

#### 1) 下单不再依赖收货地址

- **后端**：
  - `CreateOrderRequest` 将 `address_id` 调整为可选字段。
  - 创建订单时移除“地址存在且归属用户”的强校验。
  - 订单插入 SQL 移除 `address_id` 写入依赖（适配到店自助取衣场景）。
- **前端**：
  - 订单确认页移除地址区块与“必须选地址”的校验逻辑。
  - 下单请求不再传 `address_id`。

#### 2) 页面与流程精简（降低复杂度）

- 首页与个人中心移除与闭环无关的入口与请求，仅保留核心路径入口。
- 详情页移除“加入租赁车”，保留“立即预定/联系客服”，并修复底部按钮布局溢出问题。

#### 3) 管理端基础可用性补强

- 管理端页面在前端对非管理员角色进行访问拦截与提示。
- 管理端通过统一 API 进行订单检索与财务操作（退押/扣费）。
