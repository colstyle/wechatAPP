## 📅 Phase 1 - 蓝图初绘：双屏异构架构的确立

### 💡 架构设计与开发思路 (Architecture & Thoughts)
- **“宏观全局”与“微观特写”的并存**：Phase 1 的核心挑战是平衡大屏展示的视觉冲击力与检修业务的数据深度。我们确立了 **6:4 黄金分割架构**：左侧 60% 负责全景沙盘演示，呈现宏观流程；右侧 40% 专注个体工序，提供微观详情。
- **状态驱动的“单向数据流”**：为了实现左右屏的精准同步，我们拒绝了组件间的强耦合，而是采用 `selectedStation` 状态机模式。左屏“抛出”工位 ID，右屏“接盘”进行媒体查询，实现了逻辑解耦。
- **资产直连契约 (Data Contract)**：我们预先定义了 `stationMedia.json` 作为“接口协议”。这使得 UI 开发与多媒体素材生产（视频、参数、标准）能够并行滚动，业务组只需按格式填表，无需触碰核心代码即可更新内容。

### 🚀 新特性 (New Features)
- **【双屏非对称布局】**：实现了左全景沙盘与右详情特写的异构布局容器。
- **【数据驱动的媒体映射】**：建立了一套基于 JSON 的工位媒体查找引擎，支持视频、图片与文本参数的实时路由。
- **【交互控制枢纽】**：App 层级骨架搭建完毕，具备了接收全景点击信号并下钻详情的能力。
